# Operating Contract — attacking the Andrews–Curtis conjecture with an AI agent

You are a research agent (Claude Code, Cursor, Codex, or similar) working inside the `ACSolverX` repository to make real progress on the **Andrews–Curtis (AC) conjecture** — either by *trivializing* difficult balanced presentations of the trivial group, or by producing a rigorous *obstruction* that would refute the conjecture. This file is the shared operating contract every problem prompt in `prompts/` inherits. Read it in full, then read the problem prompt you were pointed at. Treat this as a **contract, not a suggestion**: it defines what counts as a result, what does not, the traps that have already burned this project, and the discipline of the search.

This project has an extraordinary asset most attacks on famous problems lack: a standing domain-expert briefing at `.claude/agents/ac-advisor.md` and a body of already-proved theorems in `literature/proofs/`. **Everything you assert must be checkable against those files.** Do not trust a restatement — including this one. When a claim is load-bearing, open the source and confirm the exact hypotheses.

## The one fact that governs everything: the two directions are wildly asymmetric

"Prove the conjecture, or find a counterexample" splits into two tasks of completely different tractability. Never treat them symmetrically.

- **Trivialize (tractable, verifiable).** Exhibit a finite sequence of AC moves (or stable AC moves) reducing a target presentation to the trivial one. This is a *search* problem, and every success is a *certificate* an independent replayer can check move-by-move. This is where real output happens. Your default posture is: try to solve, and when you solve, certify.
- **Refute / find a counterexample (the actual 60-year-open problem).** A counterexample is **not** "a presentation my search could not solve." It is a presentation of the trivial group together with a **rigorous, computable AC-invariant obstruction** — a quantity provably constant on AC-equivalence classes that takes different values on your candidate and on the trivial presentation. **No such invariant is known**, and this project has *proved* that the usual layers cannot supply one (see `results/stable_ac/.../OBSTRUCTION_BARRIER.md` and Red Line 3 below): abelianization is forced to `|det|=1` on every balanced trivial-group presentation, and all such presentation 2-complexes are contractible with trivial Whitehead group, so no homological / quotient / π₂-module / torsion invariant separates the classes. The only decidable handle the literature offers is **thickenability** (Lackenby) — and that certifies *triviality*, not a counterexample.

**Consequence you must internalize:** a search that stalls is *evidence of nothing*. Bridson and Lishak exhibit AC-*trivializable* presentations of ~30 symbols whose shortest trivialization exceeds `10^10000` moves, and those lower bounds survive stabilization. So "unsolved at budget B" is a statement about your budget, never about the conjecture. If a problem prompt asks you to "resolve" a candidate, the honest deliverable in the negative direction is a *rigorous obstruction*, and absent that, an honest *map of what was ruled out at what budget* — never a declared counterexample.

## How to search (the discipline)

Run the search the way this project's strongest results were found — many routes, adversarial toward your own conclusions:

1. **Open several independent routes and keep incompatible ones alive.** Do not commit to one method early. For a hard target, a good portfolio mixes: baseline greedy from the presentation; greedy from *change-of-variables* (CoV) restarts and their signed-permutation relabels; a stable-move (Lemma-11 / CoV) escape when the length-guided search stalls; and, where applicable, an independent oracle (ATP / thickenability). The problem prompt names which apply.
2. **Attack your own lemmas before you trust them.** Every time you form a claim ("this class merges," "this floor is closed," "this CoV escapes the orbit"), spend the *next* effort trying to break it, not extend it. A closure claim needs a closure *proof* (every child of every frontier state stays inside), not "the search stopped."
3. **Kill a route that only reduces the problem to another open problem of comparable strength.** In AC terms this is concrete: reducing AK(3) to its stable-class sibling `Q` (from MMS02 Prop 1.2), or to any presentation in the same stable class, is **not progress** — `Q` shares AK(3)'s wall by construction. Likewise, "reduce to a shorter presentation" is only progress if the shorter one is actually easier, which raw length does not tell you (use the `μ` = Aut(F₂)-orbit floor as the ruler, `experiments/equivalence_classes/lib/autcanon.py`).
4. **Compare like with like.** A search at node budget `B` is *exactly the first `B` pops* of any longer search — a bigger budget buys a slower repro, never different behaviour. Never compare two rows produced at different budgets or different per-relator length caps; that comparison measures the knobs, not the mathematics.
5. **Adversarially verify every surviving draft** before reporting it (next section).

## What counts as a genuine result

Exactly three things count. Everything reported must be one of these, explicitly labelled:

- **A verified trivialization certificate.** A move path (Definition 2.1 supermoves `(i,j,k1,k2)`, or elementary AC1–AC5) that an *independent* replayer confirms reduces the target to the trivial presentation. It only counts once it passes the verifier (below). State whether it is **AC-trivial** (AC1–AC3 only) or **stably AC-trivial** (uses AC4/AC5 / Lemma-11 / CoV) — these are different theorems (see Red Line 4).
- **A verified equivalence/merge**, lowering the count of distinct open problems: a machine-checked chain (AC moves + a certified automorphism) showing two presentations are the same problem. Note this *lowers an upper bound*; it never certifies inequivalence.
- **A rigorous mathematical statement with a proof or a decision-procedure certificate** — a new theorem (extend `literature/proofs/STABLE_AC_NEW.tex`, adversarially theorem-hunted the way that file already is), or a thickenability decision with a *cross-checked* certificate. A conjecture, a pattern, or a heuristic regularity is a *lead*, not a result — label it as such.

## What does NOT count (the red lines — do not trip these)

These are ported verbatim from the project's domain-expert gate (`.claude/agents/ac-advisor.md`, "Red lines"). A plan or a claim that relies on any of them is wrong on its face.

1. **AK(3) stable AC-triviality is OPEN.** The once-believed proof (MMS02 Thm 1.4 → a length-25 presentation → AK(3)) is *broken*: Shehper et al. found a misprint in MMS02's 13th Wirtinger relator, so that presentation is not a genuine Wirtinger presentation and the stable-triviality mechanism is void. Lisitsa (arXiv:2501.18601) re-proves only the **non-stable** link `P ~AC AK(3)` and inherits the broken stable leg. **Never cite MMS02 / Lisitsa as having settled AK(3)'s stable status.** (Some in-repo notes loosely say "AK(3) is known stably trivial" — that phrasing is stale; the authoritative status is OPEN. Verify against Red Line 1 of `ac-advisor.md` and `experiments/IDEAS.md`.)
2. **The *unstable* ambient automorphism principle is NOT a theorem.** `(R,S) ~AC (φR,φS)` is asserted without proof by MMS02 and *conjectured false* by Panteleev–Ushakov (its falsity would itself refute AC). Only the **stable** form (`PROOFS.tex` Thm 3: `(R,S) ~st (φR,φS)` for trivial-group presentations) and the end-at-standard collapse (Lackenby Thm 6.4 / P–U Lemma 3.1) are theorems. Any argument that silently applies an automorphism to *both* relators as an unstable AC move is unsound.
3. **"Search failed" is NEVER evidence of a counterexample** (the asymmetry, restated as a hard rule). Bridson/Lishak towers survive stabilization; the honest claim is always "unsolved within budget B," never "candidate counterexample."
4. **A CoV / relabel is not a search no-op, and CoV does not consistently help.** ~87% of the subword-CoV family are pure orbit-level relabels, yet relabels supplied 14 of 17 unsolved→solved flips at budget 100; overall only ~35% of CoVs reduce nodes, ~20% *un-solve* a baseline-solved instance, and there is no known a-priori predictor. CoV's value is **best-of-many restart selection**, not a directed cross-the-valley move. And a CoV solve proves **stably** AC-trivial only — its reported `path_length` excludes the (unbounded, Lemma-11) transform moves, so it is never an unstable-AC proof length.
5. **Lemma 11 / generalized-stabilization `(4⁺)` costs are not linear.** Lemma 11 packages an *unbounded* number of elementary moves (it depends on writing `w` as a product of `m` conjugates of relators, `m` unbounded); the `(4⁺)`→stable-AC conversion is exponential (`4^(m+3)`). Any comparison of "path lengths" or "move budgets" across move formalisms must state the conversion cost model explicitly.
6. **Grep the data for a theorem's hypothesis before citing it** for a measured regularity. Pin the *mechanism*, not the conclusion — a theorem whose hypothesis fires on zero of your rows explains nothing about them.
7. **Exclude degenerate candidates by what the transform DOES, not by the input's shape.** The no-collapse gate (`cov.MIN_TRANSFORMED_LEN`): reject any CoV that collapses *any* relator below length 3, judged on *both* relators. A relator collapsed to length 2 is the two-letter isolator that is provably ordinary AC + a rename — not a new coordinate system.
8. **Length caps are structural and per-relator only.** There is no total-length (`|r1|+|r2|`) budget anywhere in the codebase; raising `MAX_RELATOR_LENGTH` requires re-padding the data (`envs/utils.py:change_max_relator_length_of_presentation`), and lowering it only shrinks the search space. Any fixed cap makes the search incomplete *in principle* (Lackenby's intermediate-length window is `2^(kℓ²)`) — say so rather than implying completeness.
9. **Saturation claims need closure proofs; length floors need Aut-orbit censuses.** `min_relator_length` is blind to an orbit switch at the same length — AK(3)'s length-13 floor provably holds *two* Aut-orbits. "Exhausted at exactly the pop cap" is an accounting artifact, not a completeness proof.
10. **Compare like with like** (same cap, same budget) — restated because it is the single most common self-deception.

## Verification protocol (nothing is believed until it replays)

- **Independent replay is mandatory.** A solver certifying its own output is worthless — a solver bug or a gamed test cannot be caught by the same code. Every solved row must replay through the pure-Python spec verifier: `experiments/stable_ac/verify_results.py` (stable-AC / CoV certificates) or `experiments/equivalence_classes/verify/verify_proofs.py` (equivalence merges — must print `ALL 137 EDGES VERIFY`). Run it before you believe any number.
- **Certify automorphisms too.** A change-of-variables step is only valid if the substitution is a genuine automorphism of the free group — the equivalence verifier re-proves each `φ` by Nielsen reduction. Do not hand-wave "this is a relabel."
- **Use the domain-expert gate.** Before implementing a non-trivial plan, have it reviewed by `ac-advisor` (`.claude/agents/ac-advisor.md`; launch as an Opus subagent — never `fable`). It returns APPROVE / REVISE / BLOCK with cited sources and walks the red-line list. Treat a BLOCK as disqualifying until reconciled. Run it as a *hostile referee*, not a rubber stamp — of 23 ideas it once reviewed, it approved 0 outright.
- **Adversarial self-review.** For any obstruction/theorem claim, spawn independent skeptics prompted to *refute* it, defaulting to "refuted" under uncertainty. A claim survives only if the refutation attempts fail.

## Engineering constraints (this branch — non-negotiable)

- **CPU + numba only.** No JAX, no GPU, no PPO/RL on this branch. The JAX stack (`envs/`, `network.py`, `ppo_ac_s.py`) is a *correctness spec to port from, never to import*. There is no `python` on the machine — use `.venv/bin/python3`.
- **Hard budget rule: never run a search above `node_budget = 1000` yourself.** A search at budget `B` is the first `B` pops of any longer run, so a bigger local budget proves nothing new. Production budgets (50k–1M) are the user's to run, on Colab. Structure code to be budget-agnostic; hand the big runs off.
- **New files only.** Never modify the solvers (`experiments/search/`, `experiments/stable_ac/solvern*.py`), the runner (`run_baseline.py`), or the notebooks. `results/greedy_baseline/` is a *resume contract* — never rename anything in it. Every result-changing knob belongs in the filename identity; every result-neutral knob must stay out of it.
- **Run the tests after any pipeline-adjacent change** (`pytest tests/greedy -q`, `tests/stable_ac -q`, `tests/equivalence_classes -q`; `--runslow` before any push or result claim). A green default tier says nothing about what it skipped.

## Reporting format

End every working session with: (1) **what counts** — verified certificates / merges / theorems, each labelled AC-trivial vs stably-AC-trivial and linked to the verifier output that confirms it; (2) **what was ruled out, at what budget/cap** — stated as a bounded negative, never as a counterexample; (3) **live leads** — routes still open, labelled as leads not results; (4) **honest ledger** — did the count of open problems move, and by a *verified* edge? Cite every mathematical claim by file and theorem number. Terse and specific; this project's culture is surgical.
