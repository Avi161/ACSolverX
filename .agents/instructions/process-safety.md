# Process and computation safety

No subagent may start proof, checker, census, search, or test computation. Only the procedural root launcher may start a guarded computation. Run one foreground guarded job at a time through `scripts/run_proof_guarded.py`; short mode defaults to 30 seconds and may not exceed 60 seconds. Do not rerun an unchanged timeout: first change a material condition.

A longer experiment needs the guard's explicit `--long-run` mode, a successful at-most-60-second preflight on the identical code path, and the authorization boundary in `ac-theory.md`. The default long cap is 600 seconds. A run above 600 seconds may use at most 1,800 seconds and requires the guard change and tests to be committed, logged, and pushed first plus Sol-ultra authorization. Keep exactly one numerical CPU thread and one foreground experiment, report progress at least every 60 seconds, and stop for thermal pressure, abnormal CPU behavior, an escaped descendant, loss of the controlling task, or unexpected process-tree state.

After a long run or interruption and before handoff, audit the exact relevant process tree using only safe fields. Never print unsanitized full command lines: process arguments may contain API keys, tokens, passwords, cookies, or credentials. Inspect command names and structural arguments first; if exact arguments are necessary, redact values after secret-bearing flags and assignments before any output is returned. Terminate only a process proven stale, use `SIGTERM` before bounded escalation, and re-scan to prove exit. A timeout, nonzero result, safety stop, or incomplete audit is a bounded failure, not evidence against AC or stable AC.
