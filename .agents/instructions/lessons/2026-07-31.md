# Lessons — 2026-07-31

### 2026-07-31 Keep oracle expectations out of verifier premises

- [TRAP] Adding `expected_oracle` to the generation-projection helper input made an apparently independent index check circular: the caller supplied both authenticated metadata and the expected derived answer. The canonical root alone was also insufficient because it contains no per-schema pump profiles.
- [WORKS] Production constructs a private premises record only from authenticated root and shard replay: domain, dependency count, schema pump profiles, bucket counts, and witness counts. The helper derives the complete zero-digest oracle and checks only its canonical byte length against the projection; tests freeze the full six-family oracle line as literal external evidence and never pass an expected oracle into production code.

### 2026-07-31 Delay projection premises until every shard authenticates

- [TRAP] The first streaming-verifier plan authenticated rows incrementally but never froze the handoff that constructs generation-projection premises; validating before all seven shards close would trust incomplete schema, bucket, witness, or dependency data.
- [WORKS] Authenticate every descriptor/object byte, digest, tag map, record count, and footer first. Then construct the six schema profiles with pump count `max(len(witness[2]))` across cells and call the private projection validator. This phase computes only the package-derived hash and remains nonattestable until independent source-semantic replay finishes.

### 2026-07-31 Repeated stream blocks must accept their steady phase

- [TRAP] The first bounded shared-shard phase machine advanced after one `b_identity` or `b_coordinate` but accepted the next record only from the preceding phase, so every valid multi-record block failed on its second row.
- [WORKS] For a required nonempty repeated block, accept both its entry phase and its steady phase, then leave the machine in the steady phase; keep the index-consecutiveness check as the independent guard against gaps and reordering.
- [WORKS] A mutation test aimed at a later wire guard must preserve all earlier authenticated premises: replace the terminal LF with one byte to test the final-LF guard without first changing the descriptor byte count.
- [WORKS] When phase advancement fails because authenticated descriptor counts claim more rows in the completed block, report a descriptor tag-count mismatch rather than generic row disorder; this preserves fail-closed behavior while identifying the violated premise.
- [TRAP] A zero pump count is permitted by the private premise type because it is a maximum of witness-list lengths; use `-1`, not `0`, to target its exact nonnegative-integer guard.

### 2026-07-31 Isolate descriptor tag-map mutations from the total-count gate

- [TRAP] Incrementing both one descriptor tag count and `record_count` makes the actual stream fail the total-record comparison before the intended tag-map gate.
- [WORKS] To test each per-tag census under the mandatory `sum(record_counts) == record_count` root invariant, redistribute one declared count from a singleton balancing tag to the target tag while keeping `record_count` fixed. The actual stream then isolates the descriptor tag-map mismatch.
- [WORKS] Bind per-iteration hostile payload maps as lambda defaults inside nested mutation loops; otherwise a delayed supplier can observe the loop's final map rather than the intended case.
- [WORKS] Check a retained table's fixed capacity before parsing indices or following cross-references for the next row; otherwise an over-cap row can be rejected by a secondary semantic gate and leave the explicit allocation bound unreachable.
