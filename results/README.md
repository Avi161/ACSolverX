# results/

`python run.py --config configs/<name>.toml` writes `results/<run name>/` here:

- `paths.jsonl`: one record per row (`id`, `solved`, `kind`, `aut_assisted`, `cost`, `sub_moves`, `elem_moves`,
  the certificate, the cap counters, `seconds`), written only after the certificate replays on the row. A rerun
  skips rows already in the file; `--fresh` starts over.
- `summary.json`: solved, `ac_path` / `aut_assisted` / `stable_cert` counts, cost, wall time, path lengths in
  substitution and elementary moves per kind, and the `caps` block (below).
- `config.json`: the config the records were made with.

`paths.jsonl` is gitignored (the certificates are regenerated by rerunning the config); the `summary.json` and
`config.json` of every run here (those quoted in `README.md` and in `docs/RESULTS.md` section 0 and its cap section) are
tracked. Each run's command is
`python run.py --config configs/<file>.toml --set name=<run> [--set ...]`, as listed in RESULTS.md section 0
(`config.json` holds the full config).

## Cap counters

Every record of a capped search carries the six fields of [docs/CAP.md](../docs/CAP.md): `cap` (the cap watched),
`cap_dropped` (children the cap kept out), `cap_dropped_min_total`, `cap_would_pop` (dropped states the search would have
popped), `cap_first_bind` (pop number of the first such pop) and `cap_needed` (the smallest cap at which the run changes).
The hybrid also carries the same fields under `dyn_cap_` and `slack_`, and CoV adds `cap_legs_bound`. An uncapped run
(`cap: none`) has `cap: null`, `cap_dropped: 0` and `null` elsewhere.

`summary.json`'s `caps` block has one entry per prefix (`cap`, and for the hybrid also `dyn_cap` and `slack`):

| key | meaning |
|---|---|
| `cap` | the cap(s) watched |
| `rows`, `rows_dropped` | rows, and rows where the cap dropped anything |
| `rows_would_pop` | rows where raising the cap changes the search |
| `raise_ids` | those rows, up to 100 ids: rerun them with `--rows <ids>` and the limit raised to the needed value (`--set search.cap=25`; the hybrid's `--set hybrid.dyn_cap=13`) |
| `dropped`, `would_pop` | sums over the rows |
| `dropped_min_total`, `first_bind_min`, `needed_min`, `needed_max` | least over the rows, and the range of `cap_needed` |
| `cap_legs_bound` | CoV only: searches of its rows in which the cap bound |

`rows_would_pop == 0` means the whole run is independent of the cap (any larger cap gives the same pops and paths). The
rank-n runs (`rankn`) write `rows/<id>.npz` and a different `summary.json` (docs/RANK3.md); their `cap_counters` block counts
searches that dropped a child and searches where the cap could bind. Row files (`results/*/rows/`) are not for git.
