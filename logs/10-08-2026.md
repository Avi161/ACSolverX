## 22:40:00 UTC · `176a8553`

**Dropped the early exit: every presentation now searches all 3 ranks**, on the user's instruction ("run all top 3 even if the first solves since we want a genuine mean"), and they are right that it is the better experiment. Under early exit ranks 2 and 3 would have been searched only where rank 1 failed — a harder, self-selected subset — so their means would have been worse than rank 1's *by construction* and the per-rank comparison would have been circular. Running every rank measures all three on the same 640 presentations, which is the only direct evidence that the ranking rule orders the CoV family by quality at all. The 20-presentation dry run already makes the point: abel r1/r2/r3 solve **20/20 each** at mean **66/55/55** nodes and mean path **16.9/16.5/16.6** — rank 1 is not better than rank 3 on easy rows, a fact early exit would have hidden by never searching r2 and r3 there.

Nothing is lost in the other direction, because the ranks run in order and every row already carried its running `cum_nodes`: the deployed cost is recovered exactly as `first_solve_nodes` (ranks 1..r, r = first solving rank). A presentation now has **two costs that must not be confused** — `first_solve_nodes`, what the rule would cost deployed as a solver, and `cum_nodes`, what the census spent — and `summarize()` pairs the *first-solve* cost against plain greedy, because plain greedy's number is one search that stopped when it solved, so charging the CoV arm for ranks a user would never run would compare a census against a solver. The census total is printed separately, beside a new per-rank block (solved, median/mean nodes, median/mean path, per rank).

The half of this that fails silently is resume: `_finished` now requires **all** k ranks, and a solve does not finish a presentation. Had a solved rank 1 kept counting as finished, a Restart → Run All would have skipped precisely the presentations rank 1 solved, the file would have looked complete, and ranks 2-3 would have been measured on the complement of the easy rows — the same self-selection, reintroduced through the resume path. `test_restart_fills_in_the_ranks_after_a_solve` pins it by truncating a finished file to its rank-1 rows and requiring the resume to fill the rest in; both new tests assert their fixture actually exercises the case rather than passing vacuously. The reporting half had the same defect and was caught on review: `summarize()`'s `partial` list still read "a solve finishes it" (`not solved and n_searches < k`), so mid-run a presentation solved at rank 1 with ranks 2-3 outstanding would have been reported as nothing left to do while the per-rank block printed over unequal sets. It is now `n_searches < k` alone, mutation-checked (the old predicate fails the extended test on both rules). The verifier was re-run on the *new* file shape too, since the 5-presentation check at 21:05 was made against early-exit output that no longer exists: 5 presentations per rule at budget 1,000, 15 rows each of which 10 come after an earlier rank already solved — **30/30 certificates verify, exit 0**.

Cost: every presentation is now exactly 3 searches, and the bill is dominated by ranks that never solve and burn the full 100,000. On the subset-60 overlap — the hard tail, so a pessimistic rate — **17.2% of abel's picks and 21.1% of len's are still unsolved at 10,000 nodes**; the bound is 640 × 3 × 100,000 = 192M nodes per arm and the realistic figure is well under that, but it is several times the early-exit run and the user should expect hours, not an hour.
