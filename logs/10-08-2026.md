## 19:11:45 UTC · `c8b02eee`

Adds the certificate check the replication was missing. [`experiments/ppo/verify_beam.py`](../experiments/ppo/verify_beam.py) replays every solved row of a beam jsonl through `acs_spec` **alone** — the scalar transliteration of `envs/ac_moves.py`, which shares no structure with the batched `s_move` that produced the row — starting from the presentation as read off disk, and requires it to reach a trivial presentation at exactly its recorded `path_length`. Same argument as [`stable_ac/verify_results.py`](../experiments/stable_ac/verify_results.py): a solve count is not believed until something other than the search re-derives it, and here the search is a 1024-wide beam that gathers each path through 150 steps of dedup and no-op kills, where a mis-gathered `seqs[parent]` still looks like a path. No torch, no GPU — it runs on a laptop over a Drive-mirrored jsonl.

[`tests/ppo/test_verify_beam.py`](../tests/ppo/test_verify_beam.py) tampers with real certificates and requires each damage to be caught. Writing it found the verifier's first version too narrow: it compared only the one-step-shorter prefix, so a path that solved early, wandered off and returned to trivial passed. It now records the **first** terminating step in a single replay and reports the move the path really solved on, which also turns the plain over-long case from "does not end trivial" into a diagnosis carrying the true cost.

Runtime recorded in [`PLAN.md`](../experiments/ppo/PLAN.md) from a local measurement — 240 ms per batch-1024 forward on CPU, one forward per beam step — so `beam_upstream`'s worst case is ~12 h here and minutes-to-tens-of-minutes on an A100, where a 137,765-param model is launch-bound. `ALLOW_TF32 = False` is a deliberate throughput cost: upstream pins `jax_default_matmul_precision=float32` and TF32's ~1e-3 error can flip a top-k tie.

## 19:49:48 UTC · `6359ea90`

Fixes `convert`, which died on the first real A100 run before anything else could start. **`610model` was trained on AMD ROCm GPUs** — its `params/_sharding` names `rocm:0`. Anywhere that device is absent from `jax.local_devices()` (Colab's CUDA image, this laptop) orbax logs `Device rocm:0 was not found` once per array, falls back to `sharding=None`, and deserialization raises `sharding passed to deserialization should be specified, concrete and an instance of jax.sharding.Sharding. Got None`. Every stage that reads the checkpoint went through this, so nothing downstream could run either.

[`read_orbax_params`](../experiments/ppo/transplant.py) now restores every leaf with `RestoreArgs(restore_type=np.ndarray)`. That is not a workaround for the error but the correct request: the function exists to hand numpy to `flat_to_state_dict`, a numpy restore never consults device sharding, and nothing downstream wants a sharded `jax.Array`. It also silences all 95 error lines, because the resolution is never attempted. Building the per-leaf args needs the parameter pytree out of `metadata()`, which orbax has moved twice — `StepMetadata.item_metadata.tree` today — so `_metadata_tree` duck-types the unwrap across versions; getting it wrong does not raise locally but deep inside orbax with a pytree structure error, which is why [`test_the_metadata_tree_is_found_however_orbax_wraps_it`](../tests/ppo/test_policy_and_ppo.py) pins it directly.

Reproduced and fixed against the real checkpoint in a throwaway orbax venv rather than guessed at: `read_orbax_params` → 95 arrays, 137,765 params, step 1000, and `export_npz` round-trips. With the `.npz` in hand the torch half of `parity` ran locally for the first time — 137,765 parameters transplanted, `mask_matches_logits` true, 0 reward mismatches, 0 unreduced relators, and `value_mean` 3.59 (a trained head, not an initialised one). A width-8 beam A/B against random init certified 20/20 vs 19/20 on the first 20 MS presentations and 0/20 for both at 1000–1020: at the local cap the head is trivial and the tail impossible, so neither slice discriminates — that comparison needs production width and is Colab's.

## 20:23:57 UTC · `5326550d`

Closes the cross-framework parity gate **locally**, and fixes the two things that would have made the third A100 session fail. The second run died at `ModuleNotFoundError: No module named 'distrax'` raised out of `network.py`: SETUP installed `flax orbax-checkpoint wandb`, and `network.py` imports distrax too. Adding it to the pip line is the small half of the fix — the real defect was that a **diagnostic** stage could kill the **productive** one. Nothing downstream imports JAX, so [`_jax_parity`](../experiments/ppo/run_ppo.py) now wraps the whole attempt and degrades to `{"jax_available": false, "jax_error": ...}` with a loud line, and `stage_parity` still persists `parity.json`; `beam_upstream` and `report` run either way. `_ensure_distrax` stands in a `Categorical` shim when the package is absent, since distrax drags in tensorflow-probability and is the one install here that can plausibly fail — it is on its own `pip` line for the same reason.

The gate itself was **wrong in a way that would have failed on a correct port**. `distrax.Categorical(logits=l).logits` returns `log_softmax(l)`, not `l`, so comparing it against raw torch logits differs by the per-row logsumexp: 5.98 on the shipped checkpoint, with 2.6e-06 spread *within* each row — the signature of a constant offset, not a bad transplant. The comparison is now over log-probabilities on **legal** actions; the masked entries are a −1e9 sentinel where a float32 ulp is 64, so their difference measures rounding on a constant, and the two masks are compared directly instead, which is the stronger check. Normalisation is done in numpy/float64 rather than `torch.log_softmax(...).double()` — MPS has no float64 and the gate's own arithmetic must not vary by accelerator. `parity_ok` now also requires the masks to agree and the argmax to match on every state, both exact.

Run against the real `610model` in a throwaway venv holding torch + jax + flax + distrax + orbax at once: **masks identical over 10,528 legal actions in 256 states, max|dlogprob| 3.79e-05, max|dvalue| 2.86e-06, argmax and top-10 256/256, `parity_ok: true`** — on CPU and MPS alike, so the residual is float32 accumulation through the flax net and not a device artefact. The shim path reproduces real distrax to the last bit (`3.7933267034162554e-05` both ways). The whole ladder then ran end to end at a legal local budget (8 × 100): parity → beam → `report`, 6/6 solved, all 6 certified by `verify_beam`, `parity.json` + beam jsonl + `smoke_report.json` all mirrored.

One durability fix alongside: [`run_beam`](../experiments/ppo/beam.py) takes a `checkpoint` callback fired on the heartbeat, and `stage_beam` passes the Drive mirror through it. The mirror previously ran only after `run_beam` returned, so a disconnect at hour two of the 1190-row eval left Drive holding nothing and the next session re-decoded from zero.

`.venv/bin/python3 -m pytest tests/ppo -q` → **79 passed, 2 skipped** (the two new JAX-dependent tests skip without jax and were run green in the venv that has it).
