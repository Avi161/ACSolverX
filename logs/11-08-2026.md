Relabel-dedup gate for the ms640 CoV top-3 manifests, plus the study that prices it. A top-3 slot holding a start an earlier rank already searched *up to renaming* is a wasted search: a relabel is an automorphism, so a solution exists for one iff it exists for all eight, and the minimal AC path length is identical. Measured on the shipped manifests, that waste is large — [`abel`](../results/stable_ac/cov/cov_top3/manifest_ms640_abel_top3.jsonl) repeats a relabel class on 500/640 presentations (723 redundant slots), [`len`](../results/stable_ac/cov/cov_top3/manifest_ms640_len_top3.jsonl) on 343/640 (424 slots), well above the 553/218 that Booth-canonicalisation alone catches.

New: [`cov_top3_relabel.py`](../experiments/stable_ac/cov/run/cov_top3_relabel.py) (the `abel_rd`/`len_rd` rules, built on `words.relabel_key` — the same canonical form `equivalence_classes` uses — plus `audit`/`verify`/`load_manifest`; the rules register through a scoped `registered()` context manager rather than mutating `cov_top3_manifest.RULES` at import, because five tests in `test_cov_top3.py` parametrize on `sorted(M.RULES)` at collection time and the shipped CLI builds its build-everything list from it), [`cov_top3_relabel_run.py`](../experiments/stable_ac/cov/run/cov_top3_relabel_run.py) (stage B, with a preflight that re-derives every relabel class instead of trusting the stored tag), [`test_cov_top3_relabel.py`](../tests/stable_ac/test_cov_top3_relabel.py) (25 tests), and the two deduped manifests.
