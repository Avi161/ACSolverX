**Two traps this carries a test for.** Filtering the benchmark out of the training file stops the shipped prefix walk at index 0, silently collapsing the 634-row pin to 0 in *both* arms; and the two arms share a dataset, a seed and an output directory, so a tag that did not carry the reward variant would have them resuming from each other's checkpoint.

**From the independent review**, two real changes to `heldout.py`: `build()` now compares the existing file's CONTENT rather than its row count, because a stale file of the same length would have survived as "already built" while the returned counts stayed correct — wrong only in the file a training run actually reads; and both prefix walks now reuse the lists already in memory (`ms_prefix_length(..., rows=)`), since the old log line re-`literal_eval`ed the whole 156k-row file just to print the "was" number, eagerly, even when `log` was a no-op. Two of the existing tests were also weaker than their names: the unknown-variant test asserted a bare dict raises `KeyError` without ever calling `heuristic()`, and every `lam = 0` test exercised only the `if lam == 0.0: return zeros` shortcut. Both are now asserted through the real call path, and all three fixes are mutation-checked — reverting each one turns the corresponding test red.

**And the content check turned out to be dead code where it mattered.** `run_ppo._ensure_dataset` returned early on `os.path.exists`, so `build()`'s comparison never ran for the file a training run actually reads — the guarantee held only in the tests that called `build()` directly. Found the hard way: a mutation run left `data/AC19_extended_ho60.txt` corrupted at the right row count and the next full suite consumed it happily. The existence short-circuit is gone (both builders are idempotent and now compare content, so calling them is a no-op when the file is right, at the cost of one source parse per process start — against an 8-hour run), `build_benchmark_dataset` got the same row-count-to-content fix, and the test that corrupts a file now uses a stem of its own with a `finally` repair, so a dying process can no longer poison the shared data file.
